# Qwen 3.8 Max 与 3.6 Plus：两段真实视频对比

测试日期：2026-10-18。使用本机已有 API 凭据，实际新增 **4 次付费推理请求**，没有 Mock、自动重试或权重训练。四组响应均通过 Extraction、memory Schema、实体/帧/时间引用及问答引用检查；这些检查不代表视觉事实正确。

## 模型与测试条件

阿里云官方当前将 `qwen3.8-max` 列为旗舰视觉模型，支持图像、视频、JSON 输出和最长 2 小时视频。现有 API 的模型列表包含此型号，两次真实视觉响应也均返回 `model=qwen3.8-max`，不只是检查列表。官方说明：[视觉模型](https://help.aliyun.com/zh/model-studio/vision-model)、[模型能力与价格](https://help.aliyun.com/zh/model-studio/qwen3-8-max)。本机 API 网关并非上述官方文档的计费入口，实际费率尚未核实。

两段输入分别为 `video/10月18日_逆时针90度.mp4`、`video/桌面_逆时针90度.mp4`，是目录中两段内容方向正确的导出版本。原始纵向版本未重复推理。

- 每段完整解码并按原始 PTS 抽样 0.5 fps，分别得到 91、197 帧；最后抽样时间为 180、392 秒。
- 同一段视频的新旧模型使用完全相同的 JPEG 帧、frame_id、时间戳、提示词和 Schema；均不提供已知实体或预期答案。
- 提示词为 event-v0.4，SHA256 为 `d46545f725936006a6fe52a42ef1a6939c858fb3dbaf19d3afde6c558027783d`。
- 每组将整段视频的抽样图片一次送入模型，temperature=0、enable_thinking=false、max_tokens=16384；未触发截断。
- 这是整段抽样图片的关键事件比较，**不是原生 video 参数测试，也不是生产环境 30 秒分窗测试**。不能直接将事件数量与既有分窗结果比较；0.5 fps 可能漏掉快速动作。

## 证据抽查与决定

1. **3 分钟视频有局部改善**：3.8 输出了约 60–68 秒杯子在柜格之间转移，以及约 126–128 秒蓝色圆罐被拿起；这次 3.6 输出遗漏了这两段变化。抽查对应帧可支持这些变化。
2. **柜格位置仍会标错**：3.8 把笔记本电脑与保温杯都关联到“柜格中右”。例如 68 秒画面中，电脑在左侧较上方的格子，杯子在右侧格子，两者并非同一位置。3.6 本次也把电脑标成“置物架中右格”。
3. **关键入包误判没有解决**：长视频中，3.8 声称电脑于 374–380 秒放入背包，3.6 声称发生在 376–378 秒。两者均错误：386、390、392 秒的实际帧仍可直接看到同一台电脑留在桌面。3.8 的全局视野和较大模型也未自动消除此反证冲突。
4. **退出引用仍偏早**：两者将背包离开画面的引用截止到 390 秒；该帧仍能看到门口的人和部分背包，不能据此确认已经完全离开摄像头视野。

因此，当前只能确认 **3.8 可真实调用，且部分事件覆盖改善**；不能确认它全面优于 3.6，更不能把本轮记录视为已验证事实。正式服务默认仍为 qwen3.6-plus，本轮实验没有覆盖已有 SQLite 记忆，也没有修改 `.env`、生产提示词或冻结提交包。

后续优先做入包事件的后续反证复核、柜格位置稳定命名和少量人工标注对照；再判断是否将 3.8 用作关键窗口复核模型。生产分窗、思考模式和更密集抽帧下的 3.8 效果尚未测试。
