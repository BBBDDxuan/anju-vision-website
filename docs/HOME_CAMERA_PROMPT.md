# 居家摄像头场景定制：提示词与微调的边界

本项目当前采用Qwen视觉API。给接口增加场景、动作规则和输出约束，属于提示词优化，并不改变模型权重。本轮没有执行模型训练，也没有把API推理、回归测试或历史结果保存称作“微调”。

## 当前实施

场景假设是固定机位、第三人称室内视频，关注物品的位置和变化。提示词约束：

- 注意俯视透视、弱光、反光和人体遮挡，小物体看不清时用宽泛外观名称，不能随意认成钥匙、手机或药物。
- 表面上拿起使用pick_up，只有明确从容器内部取出才用take_out；保持柜体/柜格等位置名称一致。
- 物品入包要看到同一物体的实际进入过程，并检查后续反证。开包、整理包和伸手不能证明旁边物品也入包。
- 离开画面的引用末帧必须支持已经越界；物品仍在镜头内、只是走向门口，不能说已经离开。
- 相似物与遮挡后重现不能只按颜色合并身份；不确定时标ambiguous或unknown。
- 不推断人的身份、关系、意图、健康状态或镜头外活动。容器内部不可见，不把“可能还在”写成直接观察。
- 沿用现有Extraction JSON与原视频frame_id；事件时间及证据ID由程序生成。

## 版本与真实测试

稳定基线v0.4已保存在prompts/archive/event_extraction_v0.4.md。较长的居家版本v0.5位于prompts/candidates/home_camera_v0.5.md：对3个真实开发窗口调用3次Qwen，JSON与引用通过，桌面动作和柜格拿放检查通过，但末段仍错误地把笔记本识别为入包；因此**不能声称v0.5全面优于基线，未将它保留为生产默认**。

随后形成较短的v0.6候选：先记录最后一帧仍直接可见的物品，再回溯动作，补充离开画面的完成帧要求。候选来源与实际运行版本均记录版本号和SHA256。默认提示词文件仍是prompts/event_extraction.md；最终采用版本与v0.6实际结果在完成后追加。

真实记录在evidence/home-prompt-real.json和home-prompt-v06-real.json。使用同一组已有视频帧，测试期不向模型发送预期答案；已有实体候选会作为身份参考，因此这也不是“从零识别”评测。这些片段已经用于开发和误判分析，不能算独立保留集，不计算识别准确率或家庭场景泛化指标。没有拍摄过实际家庭环境的独立测试集，会议室实拍摆拍只是相似固定机位开发样本。

每次请求保存实际提示词版本和指纹，作业与窗口缓存也带指纹。更换提示词后，不允许静默继续旧检查点。旧检查点缺少指纹时，需要从头分析；原有已完成记录可继续查询和回放，并保留原始版本说明。服务启动时固定加载提示词，修改文件后重启生效。

## 真正训练模型之前

真正的权重微调需要可训练的视觉模型、经授权的数据、人工标注和训练算力，不能只给当前聊天API加一句提示词。后续应先采集不同房间、机位、光照、遮挡、相似物与真实拿放/入包/取出的多帧样本，标注对象身份、动作、时间、证据与不可确定情形，并单独冻结保留集。再确认适用的模型权重/训练服务与资源，训练后和提示词基线比较误报、漏报、拒答和证据定位。

当前首先推进提示词、证据规则与数据标注。无需为了把项目称作“微调”而临时引入训练框架或未经验证的训练结论。

## 本轮最终决定

**当前生产默认保留event-v0.4；v0.5、v0.6、v0.7均为实验候选，没有宣称已全面改善家庭识别。**

| 候选 | 真实新增请求 | 实际发现 | 决定 |
|---|---:|---|---|
| v0.5（较长居家指令） | 3 | 桌面动作/柜格检查通过，但重现笔记本入包假阳性 | 不采用 |
| v0.6（先检查末帧） | 2 | 消除该入包误判、保留柜格动作；但末帧seen_at省略位置目标，退出引用到390秒仍不足 | 不采用 |
| v0.7（补位置目标） | 1 | 产生物品指向自身的关系，严格语义校验拒绝；未写入生产记忆 | 不采用 |

本轮合计6次真实请求，输入50901、输出6713 token，金额未确认。旧的“退出证据>=390秒”自动检查过于宽松：目视确认390秒背包仍部分可见、392秒才不见，因此回归记录追加严格判定，不能把旧布尔值解释成视觉通过。失败响应和修改前后提示词全部保留，没有通过放松校验或手填事件来获得假成功。

当前代码的52项自动化测试验证HTTP契约、版本/指纹、检查点隔离和既有业务流程，不代表提示词的视觉准确率通过。候选测试结果没有替换现有65条长视频候选记录，也没有触发整段视频重新分析。旧冻结ZIP维持其原版本；工作区源码与submission/application同步了本轮版本追踪和候选材料。

如果下一步继续优化，应先人工标注更多不同房间/机位和遮挡样本，建立独立保留集；当前少量开发片段上的反复调参不足以支持泛化结论。真正微调需要在此基础上另行确认可训练模型与算力，本轮未启动任何训练。

## 后续：v0.8 场景与状态证据优先实验（2026-10-18）

用户提出“以实际画面为基础，不随意推测”。核对后发现，v0.4 已包含禁止补全未拍到动作、检查放入后反证的要求；之前的两模型整段测试仍都出现电脑入包误判。因此不能仅靠重复这句原则就承诺解决。

新增实验候选 `prompts/candidates/scene_grounding_v0.8.md`，把原则改成明确步骤：先按实际可见柜体建立位置实体，统一按观看者方向编号；先记录末帧直接可见状态，再判断变化；只看到伸手、遮挡或物品消失时不输出已证实的进出动作；检查后续反证，存在真实再次取出证据时也不能机械否定中间动作。位置不清楚时允许使用较粗位置，不能猜格号。没有新增 Schema、权重训练或故事答案。

使用 `scripts/test_scene_grounding.py --run`，在上轮两模型对比的完全相同真实抽样帧上，对 qwen3.8-max 新增 **2 次**请求。沿用非思考模式、temperature=0、16384 输出上限；同为整段 0.5fps 图片输入，未测试生产分窗。每次请求只发送通用候选提示词、Schema、真实图片和原始帧时间信息，不发送本段视频的预期答案。

实际结果：

- 两段均通过 Schema、实体与帧引用校验，分别返回 31、13 条候选事件；数量不代表准确率。
- 长视频这次没有再输出电脑入包，且明确引用 392 秒末帧记录电脑仍在桌上。离线用指定物品 ID 问答，回答与该真实帧关联。这是该已知开发样本上的一次改善，不是泛化证明。
- 柜格位置问题仍在：3 分钟视频 68 秒实际画面中，电脑在图像左侧，候选仍称“第二行右格”。增加编号指令并没有可靠纠正视觉定位。
- 新候选漏保留 v0.4 的中文标签要求：长视频实体名称变成英文，使用中文名称且不指定物品 ID 的查询返回 unknown。这是明确的检索回归，阻止采用本候选；不得通过手改响应或硬编码别名冒充模型已正确识别。
- 其余候选事件未逐条完成人工审核；不能把不透明容器推断或末帧 seen_at 全部视为已核准事实。

因此 **v0.8 仅保留为实验候选，生产仍为 v0.4**。本轮没有更换正式模型、修改已有 SQLite 记忆或覆盖冻结提交包。下一步应保留通用中文命名约束，对关键容器动作增加独立前后帧复核，并给柜格增加可核验的图像区域参照；这些后续措施尚未实现或验证，不能称作当前已解决。

实际新用量为输入 **155,986**、输出 **4,442 token**，当天计数从 43 增至 45，未超现有 48 次上限，实际金额尚未核实。记录位于 `data/model-comparison/qwen38-20261018/prompt-v08-report.json`，含原始提取、事件摘要、问答检查和人工抽查结论；原始 API 响应位于 `data/runs/grounding-v08-qwen38-*/`。本候选实际提示词 SHA256 为 `00d1c27e20da198f55b219129ed498482db2a7096005f5268dcbd4228f48cb4b`。测试后核对两个源视频 SHA256 与输入帧一致，默认 v0.4 未改变。

本轮实际运行提示词与适配器相关自动化测试 **16 passed**，新脚本 py_compile 通过；自动化结果仅验证工程契约，不等于视觉准确率。脚本不带 `--run` 时只输出离线计划，带参数时最多新增两次付费请求，已有实验报告时拒绝重复运行。
