# 上下文推测与主分析模型更新

日期：2026-10-19。沿用 FastAPI、SQLite、React、现有 Qwen 适配器与追加式复核覆盖层；没有训练模型权重。

## 当前行为

- `.env`、公开模板和后端默认主模型均为 `qwen3.8-max`，复核模型同样使用此名称。网页显示当前主分析模型。真实请求须继续满足已有网络与计费配置及请求预算。
- 主提示词升级为 `event-v0.9`。模型逐窗检查前后画面，分别输出 observed、inferred、unknown。支持有依据的推测，不能用常识填补任意空白；没有依据仍保留未知。
- 上下文推测需中文理由、至少两个不同时刻的真实画面、有效实体与目标。理由需说明可见变化、推测动作、未拍清的部分与替代解释。Python 结构校验与跨记录语义校验共同执行。
- 记忆中继续使用 inferred 类型。新增两个显式规则：`visual_context_v1` 以实际帧为依据，`unverified_visual_candidate_v1` 表示旧模型尚未复核的关键候选；它们不能冒充基于其他已确认事件的条件推导。原有条件推导规则仍要求有效 source_event_ids。
- 既有关键候选不再一律显示“未知”，改为“候选推测·待复核”。这仅是对原始候选的保守展示，不声称重新调用了模型。人工否定、未知、纠正优先于机器；已反驳的原动作不得通过上下文模式重新作为相同动作的推测。
- 已有事件可点击“AI 上下文推测（1次请求）”，在同一次复核里判断原主张，并可提出不同的较弱替代解释。保留真实新增帧、实际用量、模型响应、原事件与复核历史。
- 时间线、LifeReplay 和问答单列上下文推测与候选推测，提供证据跳转与理由。推测不更新直接观察位置，不建立确定的包内关系，也不会自动传播为随包移动的事实；仅有推测时回答为“部分可答”。
- 原始 memories/events 不改写，原视频保留。旧分析不会因切模型而自动重跑；旧模型/提示词的检查点不能混入新分析，需从头开始。

## 验证记录

- 自动化测试使用明确标注的合成视频与 Mock 模型，无付费调用，结果见 `evidence/context-backend-tests.xml`。覆盖推测证据、理由、截止时间、未知保留、原始记忆不变、人工优先和反驳不可复活。
- 全套后端测试 **68 passed**；最后针对推测与复核模块再回归 **14 passed**，含真实合成视频 PTS 索引复用检查，记录为 `evidence/context-final-regression.xml`。TypeScript 与 Vite 最终构建通过。
- TypeScript 与 Vite 构建；浏览器测试见 `evidence/review-browser.json`，覆盖区域标定、人工纠正、上下文按钮、问答分类、证据跳转和手机布局。该浏览器流程为 Mock，不代表真实视觉准确率。
- `evidence/context-real-validation.json` 是两个真实视频各一个片段的主分析验证，最多两次付费请求、无自动重试。两次服务返回 model 均为 `qwen3.8-max`，Schema 与真实帧引用校验通过。柜格片段有5条观察与3条推测，桌面片段有7条观察与1条推测。桌面片段未输出电脑入包，实际记录电脑在桌面；这不是完整视频重跑或准确率评测。
- 真实上下文复核另外验证于独立“人工复核·桌面”记录。首次在付费请求前发生 FFprobe 时间戳扫描超时，记录在 `evidence/context-real-review.json`。修复为使用媒体处理超时，并在同次复核内复用完整原始 PTS 索引，避免局部帧和片尾重复扫描；重试记录单独保存于 `evidence/context-real-review-retry.json`。
- 重试 HTTP200，模型保留“电脑入包被反驳”的结论，并给出 `seen_at` 桌面的替代解释，系统以 inferred 保存。模型原理由含“整个视频”式范围过大的说法；实际只提供局部与片尾帧，因此展示层强制说明范围，更新提示词禁止声称全片连续状态，原始响应仍保留。没有把此理由扩展为“电脑全程没有移动”的事实。
- 本轮实际模型请求合计3次，成功3次、失败0次，输入42,343、输出3,628 token；初次媒体失败未发模型请求，未提高现有每日48次上限，实际人民币账单未知。
- 正式服务另做真实结果的只读浏览器验证：模型标识、独立推测回答、原图读取、原视频证据跳转、手机无横向溢出、页面无脚本异常均通过；没有新增模型调用或人工结论，见 `evidence/context-real-browser.json`，桌面与手机截图已查看。
- 与更新前 SQLite 备份比较，原始6份 memories 与133条 events 内容均未改变，所有6份有效覆盖层通过校验，SQLite quick_check=ok；没有写入人工结论，见 `evidence/context-data-integrity.json`。
- 分窗暂停状态发布与活动槽释放改为同步完成，修复快速点击继续时偶发的409冲突。

## 使用与限制

运行 `./start.ps1` 后打开 `http://127.0.0.1:8000/`，已运行时刷新。操作见 [人工复核指南](MANUAL_REVIEW_GUIDE.md)。

上下文范围是本次窗口内的真实前后帧；单事件复核另带局部加密及片尾帧，不等于连续看完所有中间画面。采样可能漏掉动作、相似物身份可能混淆，具体柜格和容器动作仍需人工核对。网关实际账单未核实，继续使用既有请求数上限，没有新增无限调用或自动全片复核。冻结提交 ZIP 尚未同步此版。

手工重跑付费片段检查（最多2次请求）须显式执行：

```powershell
D:\MemoryOSHomePrep\venv\Scripts\python.exe -m scripts.validate_context_real --run-paid
```

该脚本会检查真实源视频哈希，只保存片段验证报告，不覆盖正式完整视频记忆。
