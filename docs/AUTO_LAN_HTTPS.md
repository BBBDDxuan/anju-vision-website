# 自动维护局域网 HTTPS 与手机扫码配对

双击项目根目录 `start-phone.bat` 即可进入日常启动流程。也可在 PowerShell 中执行：

```powershell
cd 'D:\大学文件\比赛\天猫\anju-vision-website'
.\start-phone.bat
```

## 启动时自动处理

1. 识别有默认网关的局域网 IPv4；多个可用地址时要求通过 `-Address` 指明，避免选错网络。
2. 检查 8000 和 8010 端口。旧服务仍运行时先报错，不改写它正在使用的证书。
3. 默认在当前 Windows 用户的 `%LOCALAPPDATA%\AnjuVision\lan-tls` 保存本机 CA、签名私钥、服务器证书和地址记录。
4. 首次启动自动创建；重复启动校验并复用。当前 IP 尚未被服务器证书覆盖，或服务器证书将在 30 天内到期时，自动重新签发。
5. 优先保留同一 CA。只有 CA 临近到期、不可用，或更新证书时缺少可用 CA 私钥，才创建新 CA。覆盖之前，原文件备份到该私有配置目录的 `backups`。
6. 启动统一 HTTPS 手机网关及内部安全服务。已有账号、密码和业务数据不因证书更新而重新创建。

新生成的证书同时覆盖当前地址、localhost、127.0.0.1 和 ::1；重新签发时保留以前记录的局域网地址，以便返回之前的 Wi-Fi。判断覆盖范围读取真实证书的 SAN，单独修改 `address.txt` 无法冒充有效证书。

CA 和服务器私钥仅保存在电脑当前用户可访问的目录。自动配置不会把证书加入 Windows 或手机的系统信任库。

## 从电脑到 App

1. 保持启动窗口开启，打开启动输出的 HTTPS 网页地址。
2. 电脑登录后，右上角头像 → 家庭管理 → 生成手机连接并登录二维码。
3. 手机和电脑网络互通，App 登录页选择“扫码连接或登录”。
4. 二维码传递当前服务地址、公开 CA 指纹、服务器证书指纹以及短期登录码。
5. App 先以二维码中的服务器证书指纹校验专用下载连接，再下载 `/api/auth/pair-ca` 的公开 CA，核对 CA 指纹。
6. App 用下载的 CA 进行完整的证书链和地址验证，通过后才兑换登录码，并保存该后端地址的专用信任。

下载公开证书的首次请求不携带账号密码或登录码。私钥不会传给手机。此流程已由 v1.5.4 App 支持，无需为了本次启动脚本修改重新构建 APK。

同一地址、同一 CA 下的服务器证书续期，已配对 App 可继续校验。IP 改变后，需要重新扫码获得新地址；CA 更换后，也需要扫描新二维码重新配对。二维码两分钟内有效且仅可兑换一次，不能分享给他人。

电脑浏览器对本机 CA 的信任与 App 专用扫码信任是两个环节。首次访问自建 HTTPS 时，如果浏览器尚未信任该 CA，需核对后按电脑系统流程信任公开 CA。此修改不会静默导入系统根证书。

## 可选参数

显式指定本机地址：

以下地址为示例，应换成电脑当时实际使用的局域网 IP。日常自动启动无需填写。

```powershell
.\start-phone.bat -Address '10.1.1.76'
```

选择其他私有配置目录，目录可以尚不存在：

```powershell
.\start-phone.bat -TlsProfile 'D:\本机私有配置\AnjuTLS'
```

`-TlsProfile` 中的证书同样会被自动维护。不要把此目录分享或提交到 Git。

通过 `-TlsCert`、`-TlsKey`、`-TlsCa` 指定外部管理的 TLS 文件时，脚本保持手动模式，不自动替换这些文件。

新电脑初次部署仍需先完成项目依赖安装。本机已安装证书生成组件；其他已有环境升级代码后可执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`start.bat` 用于电脑 HTTP 服务，`start-dev.bat` 用于前端开发；本功能由 `start-phone.bat` / `start-phone.ps1` 启动。不应同时开启占用相同 8000 端口的服务。
