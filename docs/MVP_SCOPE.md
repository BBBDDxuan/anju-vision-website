# MVP范围与退出门槛

> 本文保留最初范围决策。首轮代码已实现，模拟流程已通过；真实模型验收尚未完成，当前状态见 [MVP_DELIVERY](MVP_DELIVERY.md)。

2026-10-18决策。业务功能均尚未开发。目标输入为单机位、MP4、最长60秒、最多3个关注物体；这些是首版产品限制，不是赛事规定。不得根据某一演示文件hash或固定时间点返回预设答案。

## P0：先确保闭环

| 功能 | 验收条件 | 允许缩减 |
|---|---|---|
| 本地启动 | Windows按README单条启动，绑定localhost，重启后记录可恢复 | FastAPI直接托管构建产物；不用云部署 |
| 上传真实MP4 | 校验内容/大小/时长；可处理一段未预置的新视频 | ≤60秒、建议≤100MB，超限说明原因 |
| 抽取事件 | 合法结构、时间边界、对象ID、动作、证据ID；失败窗可见 | 少量动作与关系，不能人工补全冒充模型 |
| 时间线 | 依据视频时间排序；有观察/推断标签和不确定原因 | 纵向卡片，不做三维场景图 |
| 自然语言问题 | last_seen / history / current_location / unknown四种意图；同义表达支持 | 解析不明时给澄清或说明支持范围，不硬匹配固定整句答案 |
| 基于证据回答 | 每个事实/推断有合法视频引用；未知有缺证据原因 | Python规则生成短回答，非必需再调生成模型 |
| 证据呈现 | 真实帧或片段可查看，视频ID/时间窗一致 | P0可先用关键帧；精确播放器跳转属于P1 |
| 证据边界 | 直接观察、条件推断、未知分开；不能把旧位置称当前精确位置 | 容器链不可靠时只回最后直接观察 |
| 稳定演示与故障处理 | 新上传完整跑通，3次重复无崩溃；超时/JSON异常可理解 | 真正已分析缓存回放作为备用并显著标记 |
| 最小安全回归 | TEST_PLAN中的6类核心反例实际执行并记录 | 不用大评测平台，不可省略拒答反例 |

## P1：只在P0过关后

- LifeReplay：复用检索结果展示相关实体证据卡；不自动剪辑，最多沿一层容器关系。作为唯一辅助亮点，预计1–2小时，失败就使用普通时间线。
- 点击时间线在同一视频精确跳转；须检查`loadedmetadata`后seek结果与关键帧匹配。
- 2–3种查询示例、响应式细节、批量小评估报告。
- 家庭空间/物品关系图仅作为可删除UI增强，不引入新关系推理范围。

## P2：明确不做

实时摄像头接入、24小时分析、多摄像头、Re-ID训练、复杂三维重建、云账户系统、主动安防判断、生产级持续运行。

## 停止扩张的时间点

- 10/18晚：先证明真实视频感知，不通过就缩小动作/输入条件，不开发复杂追踪。
- 10/19晚：必须有新视频上传→事件→问题→证据的可用闭环，否则暂停美化、删所有P1。
- 10/20晚：冻结功能；只修P0故障。
- 10/21中午：冻结演示版本；之后只修阻断错误，保留可运行版本与回滚包。

缓存只能替代网络故障的展示，不能替代可处理新上传的P0验收。若最终没有可用模型或真实视频，必须将交付状态写为“未完成MVP”，不能用静态设计稿代替程序。
