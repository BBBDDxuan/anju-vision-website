# 87 秒演示视频安全分析计时（2026-11-01）

## 范围与方法

原片：`G:\比赛\AI黑客松\video\10月30日.mp4`，时长 87.233 秒、2617 帧。原片 SHA256：`6f7ad12d1330a1a0eb0221acf6f3d14e5a2d48f1e9379c8cd24c534b12695fea`。

使用当前 GPU 小模型配置（含跌倒姿态恢复）和已配置的 `qwen3.8-max`，依次执行两次独立、无扫描缓存的完整扫描。第二次使用与网页相同的 `HybridSafety.scan_video` 和流式候选回调 `HybridSafety.review`，沿用现有请求台账和限额。本次只测安全流程，不包含上传、浏览器渲染、完整任务结果持久化或物品追踪。

## 实测结果

| 流程 | 完整耗时 | 求助候选首次可用 | 跌倒候选首次可用 | Qwen 调用 |
| --- | ---: | ---: | ---: | ---: |
| 小模型扫描 | 79.428 秒 | 25.340 秒 | 33.732 秒 | 0 |
| 小模型扫描 + Qwen 流式复核 | 77.126 秒 | 22.396 秒 | 40.189 秒 | 2 |

两次均扫描完成、采样 873 帧、产生 2 个候选，位置分别是原片 19.9 秒的求助和 31.4 秒的跌倒。Qwen 均返回 `confirmed`。Qwen 复核求助耗时 16.601 秒，跌倒耗时 13.175 秒；从第二轮开始计时，约 39.0 秒获得求助复核、53.4 秒获得跌倒复核。此计时并非声称小模型直接输出了已复核报警。

## 性能结论

- 两轮耗时接近。云端等待期间，本地扫描子进程继续工作，所以不能把两次 API 延迟之和直接加到完整视频耗时上，也不能据此声称“去掉 Qwen 能节约约 30 秒”。
- 单独小模型能在候选出现时立即返回本地结果，跳过每个候选的云端复核等待，并节省 API 用量；本次完整视频处理并没有显著提速。两轮各只测一次，运行顺序、模型加载、机器负载和文件缓存均影响结果，77.1 秒比79.4秒低不证明云端让扫描加速。
- 两轮本地模型推理分别约 55.1 / 53.5 秒，解码约 12.3 / 11.5 秒。873 个采样帧中 338 帧启动姿态恢复，共 1749 次姿态模型调用。后续大幅提速应重点优化本地推理和恢复触发，需保留现有跌倒回归验证。
- 网站默认“小模型候选 + Qwen 复核”流程保留。本轮没有把本地候选自动升级成已复核报警，也未新增小模型模式开关。

## 复现

在项目根目录执行（`--allow-cloud` 会实际消耗配置账号的 token）：

```powershell
& .\elder-safety\.venv\Scripts\python.exe .\scripts\benchmark_safety_timing.py --allow-cloud
```

去掉 `--allow-cloud` 只运行小模型扫描。每次在 G 盘的 `runtime/safety-timing-*` 新建证据及计时目录。完整本次结果：`runtime/safety-timing-20261101-143617/timing.json`。
