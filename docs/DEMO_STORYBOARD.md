# 110秒演示脚本与录制分镜

版本2026-10-18。**这是拍摄与讲解计划，非已完成演示或已识别结果。** 原构想的钥匙→桌面→黑包→沙发→离开画面只用作拍摄场景，系统回答必须以真实模型结果为准。若实际动作不同，旁白和结论一起修改。

## 现场讲解与视频分镜（总长110秒）

| 时段 | 画面/录制动作 | 旁白草案 | 验证点/素材 |
|---|---|---|---|
| 0–8s | 封面与忘记物品的生活场景，避免拍真实隐私 | “找东西时，我们缺的往往不是录像，而是能解释经过的线索。” | C交封面，D录自有道具场景 |
| 8–20s | 实际网页上传一段新拍MP4，露出文件名/时长与分析状态 | “拾迹 Home 将预录制视频整理成带时间证据的物品事件。” | 必须真实上传；本地运行，不说实时摄像头 |
| 20–32s | 分析进度与完成后的真实时间线；等待压缩可剪辑 | “系统抽取可见动作，并保留每条事件来自哪里。” | 长处理采用剪辑时标“分析等待已压缩，实际耗时X秒”；X用真实计时 |
| 32–52s | 输入“最后一次在哪里看见钥匙？”；展示回答和原片证据 | “这里给出的是最后一次直接观察，而不是猜测现实中的当前位置。” | 引用时间取实际事件，不用本稿固定秒数；点击/展开可核对 |
| 52–72s | 点击“重建经过”，依次展示钥匙入包、包移动等真实证据卡 | “相关线索按时间连起来。包移动后，包内物品的位置只是带条件的推断。” | P1未实现就用时间线筛选；旁白不称其自动剪辑成视频 |
| 72–92s | 问“所以它现在就在沙发吗？”；展示unknown/partial和原因 | “背包离开视野后，系统没有新的直接证据，因此不能确认钥匙现在在哪里。” | 只有实际拍到并识别离开才能这样说；否则改为“后续没有可用观察” |
| 92–103s | 切到缺失关键动作的第二段视频或其真实分析记录 | “如果关键动作没有被记录，它应当说明缺失，而不是补一段故事。” | 用真实失败边界样本；已分析记录须贴“回放”标签 |
| 103–110s | 回到封面/三个标签与本地版本信息 | “让过去可以被追问，也让每个结论有可核对的边界。” | 不放未实测准确率、实时或全屋跟踪宣传 |

## 录制前逐项检查

- 优先1920×1080、16:9、H.264 MP4、110秒，都是制作建议，**非已核实官方要求**；D在报名页核实后调整。字幕建议简短、1080p下≥28px。
- 保留原始录屏、项目/字幕源文件、封面SVG、出镜/素材权属记录；剪辑源可以是剪映工程或等价可编辑格式。当前还未创建剪辑工程/真实演示视频。
- 录屏前关闭密钥编辑器、个人聊天、浏览器账号信息、通知；确保界面与日志没有API Key。窗口只显示localhost业务界面。
- 演示环境运行3次；首次新上传可处理，重复运行/缓存状态有标识。更换视频后答案不能沿用旧结果。
- 正常路线准备一条；网络故障备用路线使用同一版本的**真实分析缓存**，界面说明回放，不伪装现场推理。无真实记录则坦诚展示未完成，不用手写fixture替代。
- UI稿中的示例文字、合成编码测试视频和手写JSON都不进入“AI实际分析结果”的录制。

## 现场失败处理

模型超时→展示可理解错误→如已有真实记录则打开并标记回放；识别失败→回看实际画面、说明当前样本边界；LifeReplay未完→保留基本时间线与证据，不临时讲尚未实现的功能。评分或准确率如未完成，只介绍测试方案和实际运行的案例。
