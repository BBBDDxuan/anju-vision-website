# 实时摄像头 GPU 调整

- 网页摄像头火焰扫描开始间隔由 200 ms 改为 100 ms（上限 10 FPS）。实际结果还受输入、姿态提交频率和推理耗时约束。仅保留最新待处理帧，不积压历史画面。
- 预览与姿态仍保留约 20 FPS 上限；15 FPS 摄像头不会因此产生更多真实帧。
- CUDA 实时模式自动启用困难姿态补充检测：仅缺失、不可靠、倾斜或宽人体框触发；每次最多一个旋转方向，依次尝试顺时针、逆时针、180 度。使用已有置信度、关键点和去重规则。
- 补充检测最短间隔 200 ms，按最近一次耗时延长等待，目标占用不超过约 15% 墙钟时间。它仍是同步单次推理，会增加被选中帧的延迟；不是严格的 FPS 保证。空画面也可能触发，但同样受预算限制。旧骨架不会复用成新观测。
- 离线扫描及 CPU 模式继续使用原配置。离线启用的完整多方向恢复不受实时预算影响。
- 疑似事件已有独立线程的 Qwen 复核、有界队列和确认后报警机制，本次沿用；不增加第二套复核模型或额外云端调用。复核是否可用取决于原有配置。
- 状态增加 `pose_recovery_enabled`、累计 `pose_recovery_frames` 和最近一次 `pose_recovery_ms`。

## 在 RTX 5060 笔记本验证

同步代码并重启后端和摄像头分析，无需更换权重。用相同视频或场景比较姿态 FPS、火焰 FPS、动作识别耗时和近期姿态采样最大间隔。包含正常站立、空场景、横卧和原有误报场景。目标是火焰接近 10 FPS，正常站立无补充推理，困难帧有补充尝试；不承诺识别准确率或硬件 FPS 提升。

本地自动化只验证调度、坐标恢复和事件复核行为；需在目标笔记本实测 GPU 竞争和识别效果。
