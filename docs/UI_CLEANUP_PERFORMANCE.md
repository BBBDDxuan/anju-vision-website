- 移除主页“数据盘可用…”文字及历史结果回放说明横幅。存储空间检查与历史模型记录仍正常保留在后端。

## 按需抽帧与窗口数

超过120秒的录像当前采用30秒窗口、28秒步长，前后重叠2秒；每秒0.5帧，通常每窗15帧。只抽取本次准备识别的窗口，调用模型后保存事件与证据，再处理下一窗，预算用完后暂停并保存检查点。

窗口数按时长计算，并非固定14个：`max(1, ceil((时长秒数 - 30) / 28) + 1)`。3分钟约7窗，393.633秒录像14窗，24小时理论约3086窗。120秒及以下仍使用8秒窗口、6秒步长、1fps。

## 已确认的性能证据

- 同一393.633秒真实视频的0–30秒窗口，本地抽帧原用时29.766秒，限制输入解码范围后4.638秒。两次各15帧，时间戳一致，JPEG内容SHA256逐一相同。该结果仅覆盖一个窗口的本地抽帧，不代表整片推理有相同比例的提速。
- 对照记录：`evidence/window-extraction-performance.json`。本地对照没有调用模型，未重跑完整视频。
- 当前用户启动的Qwen3.8分析前5个请求分别耗时约37–44秒；这是客户端HTTP请求总耗时，包含图片发送、服务等待及结果生成，未获得服务端内部推理/排队细分。
- 单视频窗口按顺序识别，以复用前窗实体。以每窗约40秒估算，14窗仅模型请求就可能需要约9–10分钟，另加抽帧与持久化耗时。
- 当前任务还出现MODEL_TRUNCATED：部分窗口达到2048 token输出上限，未产生有效完整结果。失败窗口以后补处理会增加耗时。本轮没有偷偷降低模型/抽帧率，也没有提高付费输出预算或自动重跑失败请求。
