# 安居视界：安装与使用说明

当前源码更新：2026-10-21（此前2026-10-20压缩包为旧版快照）。当前是面向独居老人关怀与家庭危险识别的单机位上传录像分析原型：视频上传 → 抽帧 → Qwen 视觉分析 → SQLite 事件记忆 → 带证据问答、时间线与踪迹回溯。物品查找为辅助功能。尚未连接实时摄像头或手机推送。

## 1. 环境和首次安装

本轮验证环境为 Windows、Python 3.13。需要安装 Python 和项目依赖；导入新视频还需要支持 H.264 的 FFmpeg、FFprobe。压缩包不包含 Python 环境、Node 依赖、FFmpeg 二进制、API Key 或模型权重。

将 ZIP 完整解压到一个可写目录，不要在压缩包预览窗口内直接运行。前端已构建，正常使用不需要 Node/npm。进入解压目录，在 PowerShell 执行：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\start.ps1
```

也可安装完成后双击 `start.bat`。PowerShell 执行策略拦截时：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

指定已有环境或换端口：

```powershell
.\start.ps1 -Python 'D:\你的环境\Scripts\python.exe' -Port 8019
```

默认打开 http://127.0.0.1:8000 ，点击首页“打开监测工作台”进入功能页。更换端口后使用相应地址。Ctrl+C 停止服务。服务仅监听本机；手机布局适配不等于已开放手机远程访问。

## 2. 无 API Key 的历史结果演示

交付包的 `demo-recording/` 是一份已保存的真实 Qwen 模型分析，来自 CAUCAFall Subject.2 模拟向后跌倒。启动脚本会导入它，重复启动不会重复导入。

在工作台选择“已保存真实模型分析 · CAUCAFall S02”。可以查看事件、红色跌倒候选、原片证据，选择人物进行踪迹回溯，或问“人物1什么时候跌倒？”。导入和查看不调用模型，不代表现场重新识别，也不代表已确认真实事故。

未通过启动脚本启动时，可先运行：

```powershell
.\.venv\Scripts\python.exe scripts/import_demo.py
.\.venv\Scripts\python.exe -m uvicorn backend.main:create_app --factory --host 127.0.0.1 --port 8000
```

没有 Key 时，新视频的 AI 分析按钮不可用；这是预期行为，不能用历史结果冒充新分析。

## 3. 配置新视频的 Qwen 分析

编辑本地 `.env`，不要把密钥写进代码、截图或公开 ZIP：

```dotenv
VLM_PROVIDER=qwen
VLM_API_KEY=填入你自己的Key
VLM_BASE_URL=填写与你的Key匹配的兼容API地址
VLM_MODEL=qwen3.8-max
VLM_ENABLE_NETWORK=true
VLM_BILLING_MODE=request_limited
MAX_MODEL_CALLS_PER_DAY=60
MAX_MODEL_CALLS_PER_VIDEO=16
MAX_FRAME_REFERENCES=256
MAX_OUTPUT_TOKENS_PER_VIDEO=32768
```

模板地址是本项目曾验证的服务地址，不保证适用于其他服务商或账号；模型名和地址须按实际服务商配置。修改后重启服务。`request_limited` 控制请求数，不是人民币金额硬上限；失败和重试也计数。每日60次与每批16次是不同的限制，批次会自动接续，每日额度用完则保存并暂停。

FFmpeg/FFprobe 在 PATH 中时无需指定，否则填写 `.env` 中的 `FFMPEG_PATH` 和 `FFPROBE_PATH` 绝对路径。不要照抄其他电脑的路径。HEVC 原片需要支持 HEVC 的解码工具；包内已提供 H.264 的 `video/火光_可上传.mp4`。

## 4. 从上传到查看结果

1. 打开监测工作台，导入本地 MP4。先确认播放方向、时长与画面正常。
2. 点击“开始 AI 分析”。批次自动接续；手动暂停会等待当前请求结束、保存后停止。
3. 查看覆盖范围。失败窗口、静止过滤和未分析时段不能当作“没有发生事件”。点击“继续分析”可恢复未完成任务；不同提示词或抽帧配置不能直接混用旧检查点。
4. 默认先看“安全概览”，集中查看人物重要事件与环境危险候选。再按人物、环境危险、全部事件切换；物体事件保留为辅助入口。人物分一般和重要事件，默认重要。红色表示重点关注的候选，不能当作已确认事故。
5. 绿色表示较高可信，黄色表示谨慎参考，低可信记录隐藏。推测不会仅因高自评分变成事实，颜色不是准确率。
6. 重复记录默认折叠；展开可逐条查看原始时间和证据。点击时间引用或“查看视频证据”跳转原片并查看关键帧。
7. 在“询问录像中的情况”输入“视频中什么时候有人跌倒？”或“视频中有没有明火？”，点击答案时间引用回看证据；也可在“踪迹回溯”选择具体人物或物体。物体事件分类支持查询“电脑显示器最后在哪里出现？”。
8. 删除入口位于录像库或当前视频区。删除前会确认；不要依靠删除录像来重置费用账本。

浏览器通知需要权限并保持页面打开。手机推送、实时摄像头接入、用户账户、多摄像头和高级身份追踪暂未实现。

### 短暂火光增强采样

默认对不超过120秒的录像启用4帧/秒、4秒窗口、3秒步长（窗口重叠1秒）。对应 `.env` 可选项：`SAFETY_SAMPLING_ENABLED=true`、`SAFETY_SAMPLING_FPS=4`、`SAFETY_WINDOW_SECONDS=4`、`SAFETY_WINDOW_STRIDE_SECONDS=3`。首次点火的亚秒级片段不再只依赖整数秒画面。明确熄灭后重新点燃分别记录，火焰/火花预警不跨时间空隙合并；烟雾仍允许2秒短间隔汇总。

超过120秒的长录像维持独立的0.5帧/秒、30秒窗口、28秒步长和本地静止筛查。长片尚未实现局部火光触发后的自适应高频复查；不能将短片验证结果外推为长录像中的短暂火光均可检出。阈值与长片配置可通过 `LONG_VIDEO_*` 调整，增加采样密度会增加帧数、请求量和耗时。

已有分析不会自动重新调用模型。要应用新采样与提示词，请点击“重新分析”，不要继续旧配置的检查点；新任务保留旧运行文件。日上限仍为60次（当前本机配置），可手动暂停。预警证据展开后显示全部引用帧，避免只看首尾背景而错过中间火光。

## 5. 压缩包中的数据集

- `video/public_samples/`：CAUCAFall v5 的10段模拟跌倒样本及原始 AVI，来自10位参与者，覆盖前后左右及坐姿跌倒；不是整个数据集，也没有打包全部逐帧标注。MP4 是转换版本，来源、SHA256 与转换信息见各自 provenance 和 MANIFEST 文件。
- `video/火光.mp4`、`video/火光_可上传.mp4`：用户提供的本地测试素材及 H.264 转换版。其原始来源和对外再分发许可尚未核实，不适用 CAUCAFall 的许可说明。
- `validation/fall-suite-20261020/`：已保存的实际验证结果、逐段 CSV、联系图、网页截图与问题清单。这里的结果是历史记录；只会自动导入第2节的一份演示。
- `demo-recording/`：可离线导入的那份真实历史结果、对应视频和证据帧。

CAUCAFall 使用 CC BY 4.0，引用作者 Jose Camilo Eraso、Elena Muñoz、Mariela Muñoz、Jesus Pinto，DOI `10.17632/7w7fccy7ky.5`，来源 https://data.mendeley.com/datasets/7w7fccy7ky/5 。分享或展示时保留作者、来源、许可及格式转换说明。

2026-10-20旧交付包的火光素材当时仅验证格式与播放；2026-10-21当前源码通过真实Qwen的3次请求，在这段9.9秒打火机视频中提取出3个独立明火事件、3条提醒和3条问答观察。该结果仅针对这一段受控火源样本，不代表烟雾、火花或真实家庭火灾的识别准确率。用户早期的私人居家录像、运行数据库和全部 API 响应未纳入旧包。Toyota Smarthome 授权长视频未下载。

## 6. 当前验证结果与限制

10段模拟跌倒视频均产生过 fall 候选：9段完整完成，S01存在窗口缺口；S09动作字段与说明结论矛盾，不能按10段全部识别正确统计。另有全局人物问答、持续躺卧分组及颜色理由混用问题。详见 `docs/FALL_VALIDATION_REPORT_20261020.md`，这些问题保留在交付基线中，未隐藏或补造结果。

片长上限配置为24小时、文件上限64GiB，但没有完整24小时实测；实际受存储、模型速度、采样和预算限制。长片会先做本地静止筛查，再分析变化片段与周期抽查。所有跌倒样本都是正样本，尚不能评估正常活动误报率或真实老人跌倒准确率。观察与推测都需要结合原片核对。

## 7. 数据、开发与故障排查

上传原片、抽帧、SQLite 和模型响应在本地 `data/`，可用 `DATA_DIR` 修改。模型分析会将采样图像发送到配置的服务商，上传自己的视频前应确认素材使用范围。

- 提示缺依赖：在同一个 Python 环境安装 `requirements.txt`。
- 缺 FFmpeg/FFprobe：配置可执行文件路径，重启后再上传。
- 端口占用：打开已有网页，或使用 `-Port 8019`。
- 识别缺口：查看失败区间，再继续分析；结果结构合格仍不保证语义正确。
- 修改前端：进入 `frontend`，执行 `npm ci`、`npm run build`。仅使用交付界面不需要这些步骤。
- 开发测试：安装 `requirements-dev.txt` 后执行 `python -m pytest -q`。浏览器脚本另需 Playwright 和可用的 Chrome。测试中 Mock 与真实模型结果有明确区分。

`MANIFEST_SHA256.json` 记录打包文件校验值；ZIP 旁边的校验文件记录整个压缩包 SHA256。第三方前端运行代码许可见 `THIRD_PARTY_NOTICES.md`。原创产品代码未擅自指定额外开源许可。
