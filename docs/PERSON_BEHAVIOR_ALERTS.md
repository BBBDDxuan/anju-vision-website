# 居家摄像头系统：匿名人物行为与网页预警

2026-10-20。产品现名“安居视界”，副标题“居家视频监测系统”，功能页面为“监测工作台”；已有录像与内部ID保留。

## 事件分类与动作表述

工作台的“事件分类”可切换全部、物体事件、人物事件。人物事件再分为一般事件和重要事件；重要事件只包含摔倒、求助和长时间未出现，在上方红色卡片中独立展示并支持证据回看。行走、坐下、起身、攀爬、地面躺卧和操作物体等归一般事件；内部无人采样记录不逐条混进用户事件，仅用于计算长时间未出现。

按明确的`entity_type`区分人物和物体，不靠名字猜测身份。人物是动作主体时显示主动句，例如“人物1（黑色短袖短裤）拿起白色保温杯”；物体是主体时保留“白色保温杯被拿起”。时间线、来源展开、人物回放及问答保持一致。人物操作的物体不作为该人物的位置或容器；不为物体事件补造动作执行者。缺少明确被操作物体的新人物交互标为未知。

已有视频中的同类句式刷新即可修正，无需重新调用模型；原始事件及证据保留。新分析使用v1.3提示词明确人物、物体和容器的角色，旧未完成任务不能混用新提示词继续。

人物出现但没有具体位置时显示“出现在画面中”；人物行走关联储物柜时显示“在画面中行走（位置参照：储物柜）”，不补出走向或抵达。旧记录将人物move与背包等物体绑定时，显示“有与背包相关的活动（具体动作关系未明确）”，保留原理由与证据，不猜测是人物移位还是人物操作物体；此类关系最多黄色，且不把关联物体计作人物位置。新模型结果若仍混用人物空间关系与物体目标，标为未知并记录原因。时间线、折叠组、回放、历史问答统一使用完整句式。

本次语义补充通过25项后端、36项前端定向测试及已有真实录像的4项只读检查，见`evidence/event-phrasing-backend-tests.xml`、`event-phrasing-frontend-tests.xml`与`semantic-real-check.json`。原始事件与模型请求数未改变；没有用文本润色替代新的视觉证据。

本次完成30项后端、31项前端定向测试和一次12项模拟浏览器流程，报告为`evidence/event-category-backend-tests.xml`、`event-category-frontend-tests.xml`及`safety-browser.json`。未新增付费模型调用。

## 如何使用

1. 打开 `http://127.0.0.1:8000/`，进入监测工作台。
2. 上传含人物的MP4，点击开始分析。旧分析结果不会自动补出人物行为，需要重新分析；新提示词指纹与旧版不同，旧的未完成任务不能混用提示词继续。
3. 在“人物行为预警”查看待关注事件，点击“查看视频证据”定位原片并展开证据帧。点击“标记已知悉”保存通知处理状态，不会修改模型观察。
4. 如需本机系统通知，点击“启用浏览器通知”并在浏览器允许。新提醒到达时触发通知；首次打开已有历史提醒不补发，页面内不重复发送同一条通知。需保持页面、后端服务及电脑运行。
5. 可问“人物1什么时候跌倒？”或“人物1的经过是什么？”。人物编号是视频中的匿名候选，不是经验证的现实身份，也不跨视频保证同一人。

## 行为与规则

- 支持出现、离开视野，以及行走、坐下、起身、躺下、地面躺卧、疑似跌倒过程、攀爬、疑似求助动作。
- 人物实体标记`entity_type=person`，只保留匿名外观描述，不进行人脸注册或具体身份识别；人物行为至少需要两个不同时刻的证据。
- 疑似跌倒、求助与长时间未出现统一标红，表示重点关注，而非确认危险或识别正确率；推测保留推测说明，低于0.55及证据不足的候选仍不展示。时间线和人物回放中的跌倒、求助事件同步标红，其他事件继续使用绿色/黄色置信分级。
- 长时间未出现默认5分钟：必须先出现人物，再有明确`no_person_visible`无人观察，且已分析范围无缺口、无人证据跨度达到阈值，才产生红色规则提醒。无人观察需要高分、清晰原片、多时刻证据；人物再次出现、未知、证据缺失或分析断档会打断计时。不从模型遗漏人物或视频尚未分析推断无人，也不保证采样间隔内绝对无人。仅指同一摄像头画面，不识别具体身份、不证明人不在家。
- 可在`.env`设置`PERSON_ABSENCE_ALERT_SECONDS=300`调整阈值（最低60秒），修改后重启服务；页面显示实际阈值。已有结果没有无人观察时，不会自动生成长时间未出现提醒，需用新版提示词重新分析。
- 地面躺卧的证据跨度至少10秒时提醒；只是多个采样时刻有证据，不证明期间持续静止，更不诊断昏迷或受伤。正常坐下、躺床、行走不会仅因该动作产生异常提醒。
- 攀爬列为注意观察；低于0.55、未知、无有效证据、主体并非人物的记录不生成预警。相邻重叠的同类人物异常合为一条提醒，保留全部来源；“已知悉”跨刷新、重复保存和服务重启保留。
- 提醒随每次有效记忆保存产生，不等整段录像完成；生成延迟仍受抽帧、窗口长度、模型速度与每日请求额度影响。

## 能力边界

当前输入仍是上传录像，所有提醒明确标注历史片段，不能当作当前现场警报。用户选择手机通知稍后配置，本轮没有接入远程推送、实时摄像头或后台手机App。浏览器通知是否实际展示还受系统通知权限与浏览器设置影响。人物分析是照护辅助，不能替代实时照护或紧急呼救；采样可能漏掉短暂动作，未提醒不代表安全。

API：`GET /api/videos/{id}/alerts`返回当前分析的提醒、证据与帧，`POST /api/videos/{id}/alerts/{alert_id}/acknowledge`标记已知悉。SQLite新增`safety_alerts`，删除录像时级联清理；原始视频、记忆、每日额度不因本次更名改变。

## 本轮验证

34项人物/预警/证据问答定向测试通过，前端类型检查与构建通过。浏览器流程使用显式模拟模型、合成视频与模拟Notification接口；报告为`evidence/safety-browser.json`。没有运行全量回归或新增付费模型请求。真实人物行为、异常检出率、操作系统实际弹窗及完整24小时视频尚未实测。
