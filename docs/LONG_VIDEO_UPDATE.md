# 长视频支持更新（2026-10-18）

> 本文记录2026-10-18的历史默认值与验证。当前时长上限已改为24小时，并采用按需分窗抽帧；现行配置和验证边界见 [24小时与手机界面更新](DAY_VIDEO_UI_UPDATE.md)。

当前程序默认允许最长3600秒（1小时）、2048MB的单机位MP4，均可通过环境变量配置。这是产品安全默认值，不是已对1小时素材完成识别性能评测的声明。当前使用用户提供的完整6分33秒原片验证。

## 具体变化

- FFprobe仅输出时间戳到磁盘，逐条匹配OpenCV解码，取消7200原始帧上限，不把长片所有帧的完整JSON一次载入内存。抽样帧仍有可配置上限14400。
- 可兼容播放的H.264/yuv420p、零起始PTS素材直接重封装，避免长片重复编码；其他格式用可配置的1800秒媒体处理时限转码。
- ≤120秒使用原1fps、8秒窗口/6秒步长。更长的视频默认0.5fps、30秒窗口/28秒步长：6分33秒约14个窗口，而短片策略需要66个。采样变稀可能遗漏快速小动作，不能据此声称识别质量相同；参数可以调整。
- 每个窗口保留独立2048输出token预算，不会随视频变长被整片均分到几十token。兼容原MAX_OUTPUT_TOKENS_PER_VIDEO配置，目前该值限制每次启动/继续的批预算，默认8192。默认每批最多4窗口，受请求/帧预算共同约束。
- 逐窗保存检查点、结构化事件与状态。达到批预算明确显示“已保存进度”，保留进度比例与未处理窗口；点击“继续分析”从检查点继续，复用帧与已完成事件。重启后也可以继续。不是把未处理部分标成成功。
- 抽帧设置或模型变动时拒绝混用旧检查点，可恢复原配置继续或主动从头分析。跨批实体ID、时间戳与证据引用保留。
- 长片实体候选只向模型提供最近使用的最多80个，避免提示无限增长；长时间离开又出现的同物关联仍可能失败，不承诺高级重识别。

## 配置

| 变量 | 默认 | 作用 |
|---|---:|---|
| MAX_VIDEO_SECONDS | 3600 | 上传时长限制 |
| MAX_UPLOAD_MB | 2048 | 上传大小限制 |
| MEDIA_TIMEOUT_SECONDS | 1800 | 单次媒体工具超时 |
| MAX_SAMPLED_FRAMES | 14400 | 落盘抽样帧数量上限 |
| LONG_VIDEO_THRESHOLD_SECONDS | 120 | 超过此时长启用长片策略 |
| LONG_VIDEO_SAMPLING_FPS | 0.5 | 长片每秒抽样率 |
| LONG_VIDEO_WINDOW_SECONDS | 30 | 长片分窗长度 |
| LONG_VIDEO_WINDOW_STRIDE_SECONDS | 28 | 长片窗口步长 |
| VLM_OUTPUT_TOKENS_PER_WINDOW | 2048 | 单窗输出上限 |
| MAX_OUTPUT_TOKENS_PER_VIDEO | 8192 | 每批总输出预留（兼容旧变量名） |
| MAX_MODEL_CALLS_PER_VIDEO | 12 | 每批请求上限（兼容旧变量名，重试计数） |
| MAX_FRAME_REFERENCES | 128 | 每批帧引用上限，重复帧也计数 |
| MAX_MODEL_CALLS_PER_DAY | 24 | 示例默认日请求上限，跨批累计；本机付费测试后手动使用额度为48 |

日请求数、RMB已确认单价模式的单视频累计预算不会因继续分析而清零。本轮限量模式仍无法声称人民币金额硬上限；如需更大规模应先核实账单单价。修改配置需要重启服务，不能通过连续点击绕过日限制。

## 使用

上传原片，无需手动剪成60秒。页面显示全片预计窗口数、每批窗口数及今日剩余请求。分析暂停后仍可查看已有事件并提问，但回答会注明分析未完成；点击“继续分析”处理后续。只有全部窗口校验通过才显示完成。已保存的完整长片记录在下拉框中可直接重新打开，回看不重新调用模型。

新增API：GET /api/videos/{video_id}/analysis-plan；POST /api/videos/{video_id}/resume。原上传、事件、问答、LifeReplay与媒体API兼容。

## 验证边界

- 49项后端测试通过，包括7501原始帧、分批暂停/重启续跑、避免重复窗口、批输出预算、缓存恢复、缺目标动作降为未知、精确替换复核窗口及配置变更拒绝续跑。
- Chrome上传72秒合成视频，分6批处理12窗口、刷新后继续、71秒证据跳转均通过；视觉明确为Mock，0付费调用。
- 完整393.633秒、约225.9MB真实原片上传与处理通过；1fps抽394帧、66个旧策略窗口，全片链路及393秒证据检查通过。视觉明确为Mock，不是长视频Qwen效果结果。
- 同一完整6分33秒原片的真实Qwen测试通过：197抽样帧、14个窗口，首次完整结果64条候选事件，原片后段证据到392秒。发现缺目标关系导致整窗拒绝并在续跑重复请求，修复为明确未知、缓存恢复且先处理未尝试窗口。首次与修复累计17次调用，后续原帧单窗复核1次，共18次新增付费调用；本轮输入166648、输出18493 token，人民币金额未知。
- 视觉核对发现“笔记本入包”的假阳性：原片380/392秒笔记本仍在桌上。增强通用反证规则后，用原始窗口重新调用模型得到65条候选，已存入当前应用。笔记本最后位置修正为桌面，不再基于该误判推断它随包离开。白线入包与背包离开仍为模型候选，未逐条人工核实，离开时间窗精度不应视为已测通过。
- 真实Chrome检查通过：65条修订事件、问答返回笔记本最后在桌面、跳转原片364秒并加载证据帧、LifeReplay、当前位置未知、刷新恢复；没有新增模型调用。不能把它等同于逐事件准确率通过。

本机为了后续手动测试完整6分33秒视频，将单批设为16次请求、256帧引用、32768输出预留，日请求上限48；这段14窗口视频可在一次启动内处理，剩余日额度不足仍会暂停。示例模板保留较小的4窗口批预算。此次自动付费测试已停止，日请求累计33次（含本轮之前15次），没有继续自动消费剩余额度。

真实记录：evidence/real-long-qwen.json、real-long-window-review.json、long-real-browser.json；修正前结果和原始API响应仍保留。当前没有独立gold标注集，不计算准确率；只验证全片链路和若干抽查事件，仍存在其他漏检或误判。
