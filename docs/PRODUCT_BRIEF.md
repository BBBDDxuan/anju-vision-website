# 产品定位与提交文案

决策日期：2026-10-18。本文的能力描述为计划，尚未实现。

## 明确推荐

做“**拾迹 Home：有证据边界的物品历史问答助手**”。用户是常在家中忘记物品去向、愿意查询已有视频的人；首版仅针对一段 30–60 秒、固定机位、少量可区分物品的真实预录制视频。用“最后在哪里看见”替代无法保证的“现在精确在哪里”。

**主方向 C：Evidence-grounded Memory Agent；辅助亮点 B：LifeReplay。** A 只保留支持这两个目标所需的事件记录和有限关系状态，不建设完整家庭监控平台。LifeReplay 首版是筛选并按序展示证据卡，不必自动剪辑成新视频。

## 三方向比较

以下是基于调研与工期的工程判断，不是市场统计或模型成绩。

| 维度 | A 事件记忆与状态追踪 | B LifeReplay | C 证据约束记忆问答 |
|---|---|---|---|
| 用户价值 | 省去翻找录像；依赖识别完整性 | 快速理解经过、方便核对 | 避免将旧位置误当当前位置 |
| 市场/研究重合 | 高，摄像头 AI、Ego4D、ESOM | 中高，检索与证据串联已有研究 | 高，可靠 VQA/拒答均已有研究 |
| 技术难度 | 通用跨遮挡/重识别很高 | 已有事件后为中低 | 规则层中低，感知可靠性仍难 |
| 3 天可行性 | 限定场景可做，通用能力不可承诺 | 证据卡版本可做 | 有限问题类型与规则可做 |
| 现场效果 | 容易像普通视频问答 | 强，答案与动作过程可见 | 强，缺证据反例能体现边界 |
| 可验证性 | 事件 F1、身份错误、状态正确率 | 证据召回、顺序、跳转 | 证据支持率、错误确定率、覆盖率 |
| 简历价值 | 数据管线与状态维护 | 可追溯检索与产品闭环 | 契约验证、风险/覆盖评估与故障处理 |
| 主要风险 | 小钥匙、遮挡、同类实例混淆 | 上游漏事件就无法重建 | 错误观察可能通过规则传播 |

你的 A 底层/B 入口/C 可信度分层合理，但三个都完整实现会超时。优先实现 C 的可验证回答契约；B 使用同一份事件查询结果；A 限制为 on/in/held_by 和可见性变化。

## 创新点写法与证据等级

- 产品设计：把查询结果组织为“最后直接观察—后续关系推断—未知边界”，允许沿证据回看全过程。
- 工程设计：不可变事件记录、规则派生状态、逐条回答证据引用、模型替换与异常校验。
- 技术改进假设：相对同一模型直接问答，状态规则和证据校验可能降低无证据确定断言；必须以同样视频、问题和预算的对照实验确认。目前没有经过验证的改进结果。
- 不能声称：首创视觉记忆、首创时序图/多模态 RAG、通用物体永久追踪、自研视觉基础模型、实时接入、已提高某百分比准确率。

## 赛事作品介绍初稿（面向完成后的产品，约 180 字）

拾迹 Home 面向日常忘记物品去向、需要反复翻看录像的人，将摄像头拍摄的预录制视频整理为可追问的事件记忆。用户上传视频后，可询问物品最后在哪里被看见，并通过时间线回看相关动作与视频证据。系统分别展示直接观察、关系推断和未知信息：当物品进入容器、离开视野，或关键动作缺失时，不把历史位置当作当前位置。项目采用多模态模型、结构化事件与可测试的状态规则，探索更透明、可核查的家庭视频问答体验。

**短版**：拾迹 Home 把预录制家庭视频变成可追问的物品记忆，用时间线和视频证据解释物品的历史去向，并在证据不足时明确回答“无法确定”。

提交前须按实际完成范围删改；开发准备阶段对外介绍应在前面加“拟实现”。
