# 腿脚不可靠时的肩髋下降候选（2026-11-06）

已补充一个复核候选入口：肩髋仍然可靠、腿脚从背景阶段就不可靠时，不再必须先判定坐姿，才能提出下降候选。这只补充送检条件，不能宣称真实遮挡问题已经解决。

## 修改范围

公共检测器新增 `OccludedCoreReview`，算法标识 `lower_body_unreliable_core_descent_review_v1`，策略版本 `fall-recovery-v7`。上传扫描与摄像头采集共用此入口，独立严格告警模式保持原实现。

先观察至少 0.5 秒、至少三个可靠肩髋观测：肩在髋上、躯干投影不超过 45 度，并且背景窗口内至少三次双脚都不可靠、跨度至少 0.2 秒。背景核心位置变化不超过参考框高度 6%。允许脚点置信度闪烁，但不会因一次弱脚点就建立“支撑未知”背景；可靠脚点情况下仍由现有支撑规则处理。

此后固定该背景参考，最长使用六秒，不随缓慢下降逐帧更新锚点。肩、髋分别下降至少参考人物框高度 15%、8%，连续可靠观测至少三个、跨度至少 0.2 秒，才提出复核候选；沿用 0.55 关节置信度、人物框置信度要求和共享事件去重。缺失人物、核心不可靠、重叠歧义、相邻框 IoU 低于 0.3，或采样间隔超过 0.2 秒会中断此背景。没有对缺失点插值，也没有根据遮挡补造触地或失去支撑。

元数据明确写明 `stable_core_posture_unknown`、`occlusion_verified=false`、`chair_verified=false`、`floor_contact_observed=false`。低置信度不等于确认遮挡；缩放单位是检测到的参考人物框高度，也不等于已知真实身高。正常坐下、下蹲、摄像头移动和姿态漂移仍可能提出候选。

该入口使用前六秒时序证据，并沿用上一轮的自适应后窗：至少一秒，运动平稳后结束，最长五秒；每次最多十二张真实图片。同事件补证、Qwen 已确认后不重复调用及不重复报警的规则继续生效。

没有修改 Qwen 提示词、接口、日额度、YOLO 权重或既有下降阈值。网页后端代码本轮未变，当前运行进程中的后端模块哈希与磁盘一致；新上传扫描/新启动摄像头的检测子进程会导入当前检测器。摄像头保持停止，没有新增云端调用，用量仍为 23/24。

## 结果及限制

- 失败复现先得到 8 项失败、12 项通过；实现后检测器全套 **634 项通过**。多帧率（5/7/10/12/15/30）、慢滑、孤立脚点闪烁、长期缺腿、弱肩髋、单关节运动、缺失、跳框、多人重叠和严格模式隔离均有合成检查。
- 相关上传、实时复核、同事件补证及流式扫描后端 **67 项通过**，全部使用本地模拟响应。
- 115 段原始姿态缓存回放中，56 段跌倒来源与 56 段正常动作的候选、证据时间戳和严格告警输出逐项不变：仍分别是 56/56、8/56 有候选。3 段本地录像仍全部有候选，候选数 7→8；`local_10-30` 在 **9.7 秒**增加一个候选，未人工核对、未云端复核。严格告警及非跌倒信号均保持一致。
- 将同一批姿态的膝/踝置信度从第一帧起全部置零后，跌倒来源候选覆盖由 **20→39/56**，正常动作候选覆盖由 **0→25/56**，本地由 **1→2/3**。新增候选不等于新增确认跌倒。这个压力测试保留了原上半身预测和人物框，**不代表真实遮挡识别率**，也不能作为独立准确率或召回率。

另对两个坐姿跌倒和一个正常坐下原视频制作了单独的像素遮挡诊断副本：固定灰色矩形 `[265,300,345,380]`，重新执行正式 GPU 扫描，原片未修改。这是人工遮挡诊断，并非自然场景遮挡数据集。

三段人工遮挡扫描中，新入口未成为实际输出来源。为诊断遗漏，另保存了真实重新推理的姿态：S04 在约 2.7～4.7 秒区间，未遮挡原片 21 个采样均有人物且肩髋可靠；人工遮挡副本只有 17 次检出人物、11 次肩髋可靠。因此，腿脚遮挡还会影响人物框和上半身关键点，新规则无法在这些观测丢失时补造下降过程。

当前完成的是“上半身证据仍可靠时放行复核”的逻辑修补。严重遮挡、肩髋也丢失、长时间弱点、摄像头运动、没有参考背景、支撑面未知等问题仍存在；恢复正常姿态后的快速重开事件在无腿脚时也仍受现有恢复判断限制。不确定结果不自动升级成确认报警。
