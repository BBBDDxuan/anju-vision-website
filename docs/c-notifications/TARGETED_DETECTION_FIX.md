# 明火与求助漏检的针对性修复

日期：2026-11-05。适用仓库：anju-vision-website，分支 codex/c-notifications-release。

本轮依据用户明确要求修复明火/求助漏检，最小范围扩展到 A 原负责的本地检测与复核接点；App 页面、公共路由、数据库结构和模型权重不变。原始 ABC 分工仍适用于其它工作。

## 问题与处理

- 明火：小目标模型分数偏低、区域随手移动、短暂漏框，使原严格规则无法累计。原 FireDetector 保持原样；仅在 SafetyCandidateCollector 启用的复核模式增加 ReviewFireDetector。候选分数门槛为 max(0.25, fire.confidence × 0.65)，当前配置为 0.39。沿用现有 hold_seconds、min_frames、max_gap_seconds，允许有限中心移动及短暂缺失；累计和最近 64 次观测的命中率均至少 70%。缺失不会增加命中帧数或刷新最后命中时间。区域冷却在严格/复核两条路径间共享，避免重复候选。
- 求助：原规则要求双臂接近伸直、双腕高于头部较大余量，在斜俯视、屈肘和透视缩短时无法命中。原 HelpGestureDetector 保持原样；新增仅供复核的双手高举挥动候选。仍要求人物和关键点可靠、双手高于肩部且接近或高于头部、与头部分离；同时要求双手相对肩部产生足够运动，至少一只手出现方向反转，并持续至少 max(0.75秒, help.hold_seconds)。低置信度、放下手、丢失人物、超时或切换视频都会清除动作历史。启用的人脸可靠性限制继续生效。
- 复核：提示词允许斜俯视下的屈肘挥动，继续排除抱头、整理头发、伸懒腰和短暂抬手；挥手不能证明真实求救意图。复核器接收候选原因、动作、持续时间、命中帧及火焰漏帧统计。只有 confirmed 才能进入正式事件/告警；rejected、uncertain 和不可用结果仍被拦截。
- 证据：复核火焰保留对应区域的 subject_bbox_hint。继续使用已有事件阶段取证策略，不改变上一轮摔倒后取证、明火/求助发生时取证的规则。

## 使用

本次只更新电脑端 website 后端，不需要重新编译或安装 App，也无需增加 .env 配置项或修改现有模型配置。

1. 重启电脑端原有服务，仍使用 start-phone.ps1 和本机当前局域网地址。
2. 实时摄像头如已打开 AI，应关闭后重新打开，让新 worker 加载代码。
3. 对已有零候选的视频选择“重新分析/从头分析”，不要继续旧检查点。检测源码与复核提示词均参与签名，旧分析配置不应混用。
4. 使用现有已配置的云端复核。缺少 API Key、额度或联网条件仍无法产生 confirmed 告警。

本轮真实云端复核、正式告警送达及真机通知未实测；只证明这两段样本现在能进入候选复核。负例为合成几何/时序和模拟复核测试，没有独立标注视频集，不能据此宣称总体准确率或误报率提升。火焰模型对灯光/屏幕的混淆仍需云端图片复核；挥手也可能是打招呼。
