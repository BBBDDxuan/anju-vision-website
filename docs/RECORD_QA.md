# 基于分析记录的录像问答

本地与公开云端均支持开放式问题，例如：

- 视频中出现了几个人？画面里同时有几个人？
- 人物穿什么衣服？在录像中做了什么？
- 按时间顺序概括这段录像。
- 视频里出现了哪些物品？人物拿起了什么？
- 有哪些需要关注的情况？是否记录了烟雾、明火、火花或疑似跌倒？

“概括/总结录像”使用整体概括格式：提炼主要活动、关键变化与关注线索，观察和推测各自最多一段，正文不列时间戳。证据时间保留在可点击引用中。只有明确要求“按时间顺序/逐条回顾”时才按关键阶段排列。关闭模型或额度不足时，本地按活动类型和关注线索生成简要概括，不再返回二十条时间记录作为摘要；这种本地概括只覆盖规则识别的活动主题，表达能力弱于模型。模型若仍返回时间线，接口标记`QA_SUMMARY_STYLE`并回退，不把时间列表直接拼成一段冒充概括。

“视频中有哪些值得关注的情况？”专门检索人物重要事件（疑似跌倒、求助、长时间未出现）与环境危险事件（烟雾、明火、火花），沿用网页预警的证据、去重与缺席判断规则。普通出现、行走、坐下、地面躺卧、攀爬及物品事件不进入此问答结果。该问题直接读取有效预警，不新增模型请求；没有符合条件的记录时明确说明未检索到，不能据此宣称没有风险。原本的全片概括与其他问题不受此筛选影响。

人数统计只使用有原片证据的直接观察。同一人物ID的重复动作不重复计数；同时人数按相同采样时刻统计，不能用事件时间区间重叠代替。统计结果是人物候选数：跨时段ID可能拆分同一人或合并相似外观，不能宣称全片准确的独立人数。没有人物记录时回答无法确定，不能断言0人。推测和低可信记录不用于人数统计。

其他问题默认将有效结构化记录发送给当前配置的Qwen模型进行纯文本解读，不上传视频或关键帧，不重新识别画面。后端核对每条结论引用的事件ID，再从原事件生成证据链接；推测必须单独展示，不能作为直接观察。引用核对不等于自动证明每句话语义正确，仍可能误解已有记录。

每次解读最多1次请求，不自动重试，共享现有每日调用上限和金额预算。相同问题、记录和覆盖状态命中进程内缓存时不新增调用；重启后缓存失效。关闭界面“使用大模型解读已有记录”可保留本地检索与人数统计；`RECORD_QA_ENABLED=false`可关闭服务端文本模型入口。接口`POST /api/videos/{id}/query`支持`use_model: false`。

2026-10-21本地与云端每日请求上限均已按用户要求改为100次（`MAX_MODEL_CALLS_PER_DAY=100`），当天历史调用继续计数；云端是所有访客共享的额度。

接口返回`answer_engine`（`record_statistics`、`record_llm`或`record_rules`）、`model_called`与`cached`用于说明回答来源。模型不可用、配额不足或引用无效时回退到本地检索并说明限制，不静默补造答案。

长回答处理：模型使用短事件编号，后端将其还原为真实事件与证据；提示词限制为关键阶段摘要，输出上限为3072 tokens，不逐项复述长时间线。若服务仍以`finish_reason=length`截断，接口通过`model_error.code=MODEL_TRUNCATED`明确说明原因，并返回带证据的本地检索摘要，不拼接不完整JSON，不自动再次付费调用。“概括这段录像里发生的事情”“有哪些值得关注的情况”等问题也支持本地回退。

问题涉及超过160条有效事件或上下文长度上限时，模型仅读取部分记录，答案明确提示截断；不保证全片统计完整。人数统计遍历所有符合查询截止时间的有效人物记录，不受文本上下文截断影响。未完成分析、静止过滤和漏检均会影响可回答范围。

本功能已同步魔搭公开创空间，首页提供四类已保存的真实分析案例。Toyota等受限数据及其记录未上传；许可不会因为“只发送记录”而自动扩大，未经相应授权请勿发送其记录给第三方服务。
