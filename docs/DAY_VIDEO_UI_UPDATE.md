# 24小时录像与手机界面更新

2026-10-19。按用户说明，本轮完成配置、处理流程和界面准备，不测试完整24小时录像，不新增付费模型调用。

## 界面

- 桌面增加侧边录像库、名称搜索、当前录像状态、模型就绪状态和使用说明。
- 导入区支持选择或拖入MP4，显示实际上传百分比；上传完成后区分文件校验与播放准备阶段。文件大小及磁盘空间不足时提前提示。
- 手机布局使用抽屉录像库与底部导航，在回放、时间线、问答间跳转；播放器使用 playsInline。
- 长录像时间以小时、分钟、秒显示；可输入时间直接跳转。短录像保留分钟、秒显示。
- 时间线可搜索物品/位置/动作，按录像小时与观察/推测/未知筛选，每页20条，避免一次渲染全天大量事件。
- 显示已完成窗口及真实分析覆盖范围；未处理片段不视为已识别。分析预算与请求额度放在可展开详情中。
- 问答与证据保留，人工复核入口移至时间线下方并默认折叠。没有将未知、机器推测或旧结果改成已确认事实。

## 当前配置

| 配置项 | 本次默认值 | 含义 |
| --- | ---: | --- |
| MAX_VIDEO_SECONDS | 86400 | 单段最长24小时 |
| MAX_UPLOAD_MB | 65536 | 单文件最大64GiB，仍受可用磁盘空间限制 |
| MAX_SAMPLED_FRAMES | 100000 | 累计落盘帧上限；默认0.5fps下全天约43200帧 |
| LONG_VIDEO_THRESHOLD_SECONDS | 120 | 超过2分钟启用按需长片模式 |
| LONG_VIDEO_SAMPLING_FPS | 0.5 | 长片采样率，可能漏掉快速小动作 |
| LONG_VIDEO_WINDOW_SECONDS | 30 | 每窗最长30秒 |
| LONG_VIDEO_WINDOW_STRIDE_SECONDS | 28 | 窗口步长 |

本机 `.env` 已同步上限。Qwen模型、网络配置、每日/每批请求数、输出预算和费用开关未提高。以当前30秒/28秒配置估算，24小时约3086个窗口请求；默认预算不会在一次操作内识别完全天。完整处理仍需结合实际账单、预算和可接受的采样策略决定。

## 处理流程

1. 新增 `POST /api/videos/upload` 原始文件流上传，浏览器通过 `X-Video-Name` 传递编码后的名称。不经过 multipart 全文件临时落盘，旧 multipart 上传接口保留兼容。
2. 上传中检查大小与数据盘剩余空间，保留256MiB余量；失败或中断清理本次新建目录。
3. 可直接播放的H.264/yuv420p、零起始时间素材优先创建同卷硬链接，避免为播放再复制一份长录像；不适用时保留原有重封装/转码流程。模型仍只接收采样图像。
4. 长片先建立窗口计划，只为本批实际需要的窗口定位、解码和落盘，不等待全片抽帧。时间来自解码的真实PTS，保留非零起点归一化。
5. 每窗保存原始结果、事件、证据和检查点。暂停/重启续跑复用已完成窗口；旧版整片抽帧检查点仍按旧模式读取，避免混合不同证据集合。
6. 复核抽帧同样改为定位短区间；只读取轻量流时间信息，不再为复核一次动作扫描全天所有帧。
